## 0. 目的とスコープ

営業・マーケティング業務を「段階的に」自動化するためのロードマップを定義する。
各領域について **Stage 0（人間が全部やる）→ Stage 1（人間承認つき半自動）→ Stage 2（自動）** の3段階で並べ、
各段階の前提条件・次段階への判定基準・human approval 必須ポイントを明記する。

**本文書がしないこと:**

- リードの収集・購入・スクレイピング
- メール / フォーム / SNS / Web 公開の実送信・実投稿
- 価格・割引・契約・返金の確定
- 他エージェントへのタスク発行

これらはすべて Michael 経由で人間 (CTO) の承認を得てから、別途の実行タスクとして扱う。

## 1. 絶対遵守ガードレール（GLOBAL GUARDRAILS）

以下の9項目は、本ロードマップの **全領域・全段階（Stage 0/1/2 すべて）** に無条件で適用される。
1つでも満たせない自動化は稼働させてはならない。Stage 2（自動）であっても本9項目は免除されない。

| # | ガードレール | 意味 | 適用のされ方 |
|---|---|---|---|
| G1 | **無差別 bulk outreach 禁止** | ICP に合致しない宛先への一斉送信・アカウント問わずの大量アプローチを行わない。ターゲティング根拠のないリストへの送信は禁止。 | 全段階。送信対象は毎回 ICP フィルタと明示的な選定理由を通過したものに限る。1バッチあたりの上限件数を設け、上限は人間が承認する。**宛先ごとに、選定理由（合致した ICP 条件、参照した公開情報の出所と取得日）を監査記録として保持する。選定理由が記録されていない宛先は送信対象にしない。** |
| G2 | **適法根拠の管理と opt-out 尊重** | 送信の適法根拠を宛先ごとに管理し、配信停止・「連絡不要」の意思表示を受けた宛先には二度と送信しない。 | 全段階。**宛先ごとに送信の適法根拠（事前同意／名刺等での通知／公表された事業者アドレスの例外 等）を記録し、根拠が記録されていない宛先へは送信しない。送信対象の法域は人間が明示承認したものに限り、法域を追加する際は G3 と同等の適合性レビューを人間承認で行う。** 適用される法令の特定と要件の充足判断は Legal / Compliance のレビューを経る。opt-out リストを単一の権威データとして保持し、全送信の直前に照合する。opt-out 済み宛先が候補に含まれた時点でそのバッチを停止。詳細は下記 G2 詳細規定を参照。 |
| G3 | **site terms 尊重** | 対象サイト / プラットフォーム（LinkedIn、各種ポータル、Google 等）の利用規約・robots・API 利用条件に反する収集・自動化を行わない。 | 全段階。新しいデータソース / チャネルを追加する前に、規約適合性レビューを人間が承認する。規約でスクレイピング禁止のソースは自動収集の対象外。**承認済みの全データソース・チャネルについて、少なくとも四半期ごとに利用規約・API 利用条件・robots を再確認し、確認日を記録する。再確認が期限切れのソースは自動収集の対象から外す。** |
| G4 | **rate limit** | 送信・アクセス・API 呼び出しに明示的なレート上限（時間あたり / 日あたり / ドメインあたり）を設ける。バースト送信をしない。 | 全段階。レート上限値は設定として保持し、人間が承認した値のみ有効。上限到達時は自動停止し、超過して送らない。 |
| G5 | **duplication prevention** | 同一宛先・同一企業への短期間の重複アプローチを防ぐ。既に対応中の商談・既存顧客・進行中スレッドへの二重コンタクトをしない。 | 全段階。宛先ごとの最終コンタクト日時と状態を単一データで管理し、クールダウン期間（人間承認値）内の再送を自動抑止。CRM 側の状態と突合する。 |
| G6 | **CAPTCHA bypass 禁止** | CAPTCHA / bot 検知 / ログイン障壁を回避・突破する自動化を実装しない。フォームが CAPTCHA を課す場合は自動送信の対象外とし、人間が手動対応する。 | 全段階。CAPTCHA を検出したら自動処理を中断し人間へエスカレーション。回避ツール・回避サービスの利用禁止。 |
| G7 | **初期外部送信は human approval** | 各領域・各チャネルで「初めて外部へ出る送信 / 投稿 / 公開」は、文面・宛先・タイミングを人間が事前承認する。テンプレート単位でも初回使用は承認対象。 | Stage 0→1 移行時、および新テンプレート / 新チャネル / 新セグメント追加時。承認は Michael が人間へ起票して取得する（起票の具体的手段は運用規約に従う）。**テンプレートはバージョン管理する。件名・本文・CTA・リンク先・適用セグメント条件のいずれかを変更した時点で新バージョンとなり、初回送信前の人間承認を要する。承認は特定バージョンに対して与えられ、他バージョンへ引き継がない。** |
| G8 | **契約・価格・返金・対外的な水準表明は human approval** | 価格提示の確定、割引、契約条件、返金、無償提供の判断を自動化しない。すべて人間が承認する。 | 全段階。自動化されたアウトバウンド / ナーチャリングは「情報提供・打診・日程調整」までに限定し、金額に関わる約束は必ず人間へ。**可用性・SLA・復旧時間・納期・生成所要時間・品質水準の対外的な表明も本項の対象とし、人間承認なしに文面へ含めない。** |
| G9 | **個人データ保護** | リード情報は個人データとして扱う。 | 全段階。① 利用目的を特定しプライバシーポリシーで公表する ② 第三者から取得する場合は取得元と取得経緯を記録する ③ 保有期間と削除基準を定める ④ 開示・訂正・利用停止・削除の請求窓口と対応期限を定める ⑤ 要配慮個人情報を収集しない。**以上が未整備の間は Stage A1 以降へ進まない。** |

> 本書の「配信キュー」「コンテンツカレンダー」は業務上の概念であり、メッセージブローカーを意味しない。
> 実装する場合も ADR-0024（DB 行そのものが durable queue、外部ブローカー不採用）に従い、
> Redis / BullMQ / SQS / Service Bus 等を導入しない。導入するなら ADR-0024 の supersede が先。

### G2 詳細規定

**法定表示（R-01）**

- 全ての広告宣伝メールは、送信者名・住所・受信拒否の通知先 URL・苦情問合せ先を本文に表示する。この4項目を欠くテンプレートは送信前チェックで検出し、当該バッチを停止する。

**opt-out の受付と反映（R-03）**

1. opt-out は受領から遅くとも3営業日以内、かつ当該宛先を含む次バッチの送信前に必ず反映する。反映完了まで当該宛先を含むバッチは送信保留とする。
2. メール返信・フォーム・電話・SNS・口頭を問わず、配信停止を意味する意思表示はすべて opt-out として受け付け、全チャネル横断で適用する。
3. 受領日時・チャネル・原文・反映日時を監査記録として保持する。
4. 自動分類の確信度が閾値未満の返信は opt-out 側に倒して扱う（fail-safe）。

**opt-out リストの保持（R-04）**

- opt-out リストは再送防止の目的に限り、必要最小限の識別子（メールアドレスのハッシュ等）で保持する。個人データの削除請求を受けた場合も、この再送防止記録は保持する旨をプライバシーポリシーに記載し、Legal の確認を経る。

> **補足ルール（PRODUCT_SPEC / ORG 由来、上記と併せて遵守）:**
> - 存在しない製品機能・根拠のない性能・架空の導入実績を文面に含めない（誇大広告禁止）。
> - **対外公開・送信に用いる生成動画・生成画像には、AI 生成である旨を明示する。実際に撮影されたウォークスルー映像であるかのような表現、正確な寸法・間取り・眺望であるかのような表現をしない。存在しない窓・扉・設備・眺望を含む素材を販促に用いない。**（表示の具体的な文言・位置・焼き込み仕様は未決の人間判断事項であり、本文書では定めない。確定するまで生成物の対外使用は都度人間承認を取る。）
> - **G8（価格・契約・返金・可用性/SLA/納期/品質水準の表明）と上記の AI 生成表示の原則は、Stage 0 の手作業による対外文面にも適用される。** 自動化の段階に関わらず免除されない。
> - PRODUCT_SPEC.md を製品仕様の基準とし、不明な仕様を勝手に補完しない。曖昧なら Michael に上げる。
> - 送信ツール（Gmail 等）を保持していることは送信許可ではない。実送信は人間承認が必須。
> - 本番デプロイ・本番 DB への破壊的変更・資格情報の変更・顧客データ削除は本ロードマップの対象外（STOP LIST）。

## 3. 段階別ロードマップ

各領域につき以下を記載する:
- **Stage 0 — 人間が全部やる**
- **Stage 1 — 人間承認つき半自動**
- **Stage 2 — 自動**
- 各 Stage の **前提条件**
- **次段階へ進む判定基準**
- **human approval 必須ポイント**

> すべての Stage で第1章の G1〜G8 が適用される。以下は領域固有の追記である。

---

### 領域 A. リード獲得 (Lead Generation)

#### Stage A0 — 人間が全部やる
- **内容:** 人間（または人間の指示下の担当）が ICP を定義し、手作業でターゲット企業リストを作る。エージェントは調査補助（公開情報の要約、整理）のみ。
- **前提条件:**
  - ICP 定義文書が存在し、人間 (CTO) が承認済み。
  - 使用してよいデータソースの一覧と、その規約適合性（G3）を人間が確認済み。
- **human approval 必須ポイント:**
  - ICP 定義そのもの。
  - 各データソースの利用可否（G3）。
  - 収集したリストを次工程（アウトリーチ）へ渡すこと。
- **次段階（A1）へ進む判定基準:**
  - ICP が安定（直近で大きな変更がない）し、手作業リスト作成のパターンが定型化している。
  - opt-out / 重複除外 / レート制御の運用ルール（G2/G4/G5）が文書化され承認済み。
  - リストの品質基準（必須フィールド、ICP 合致判定基準）が定義済み。
  - **G9（個人データ保護）の①〜⑤がすべて整備され、Legal の確認と人間承認を得ている。未整備の間は A1 へ進まない。**

#### Stage A1 — 人間承認つき半自動
- **内容:** エージェントが定義済みソース（規約適合が確認されたもののみ）から候補を集め、ICP フィルタ・エンリッチ・スコアリングを行い、**候補リストをドラフトとして提示**。人間がレビューし、承認したものだけが次工程へ渡る。
- **前提条件:**
  - A0 の判定基準をすべて満たす。
  - opt-out リスト・既存顧客リスト・進行中商談リストと自動突合する仕組み（G2/G5）が用意されている。
  - 収集レートの上限値（G4）が設定として保持され承認済み。
  - CAPTCHA / bot 検知に遭遇したら中断しエスカレーションする挙動（G6）が実装されている。
  - **G9 が整備済みであること。第三者から取得した候補は取得元と取得経緯を記録し、要配慮個人情報を収集しない。開示・訂正・利用停止・削除の請求窓口と対応期限が稼働している。**
  - **誤送信時の手順（§4-6）が定義・検証済みであること。**
- **human approval 必須ポイント:**
  - 生成された候補リストの最終承認（バッチごと）。
  - 新規データソースの追加（G3 再レビュー）。
  - スコアリング基準の変更。
- **次段階（A2）へ進む判定基準:**
  - 直近の一定件数以上のバッチで、人間の承認率が高く（例: 事前合意した閾値以上）、修正がごく軽微。
  - 誤収集（ICP 非合致、規約抵触、opt-out 済み混入、重複）の発生率が事前合意した閾値未満で安定。
  - 監査ログ（誰が・いつ・どのソースから・何件）が完全に取得できている。

#### Stage A2 — 自動
- **内容:** ICP フィルタ・エンリッチ・スコアリング・重複/opt-out 除外を自動実行し、閾値スコア以上の候補を自動でナーチャリング / アウトリーチ待ち行列へ投入。人間は事後監査とサンプリングレビュー。
- **前提条件:**
  - A1 の判定基準をすべて満たす。
  - 異常検知（収集件数の急増、ICP 合致率の急落、規約変更の検知）で自動停止する仕組みがある。
  - ロールバック手順（誤投入されたリードを待ち行列から除外する）が定義済み。
- **human approval 必須ポイント（Stage 2 でも残る）:**
  - 新チャネル / 新セグメント / 新ソースの追加は都度承認（G3/G7）。
  - 自動化の停止閾値・レート上限（G4）の変更。
  - **ICP 定義・スコアリング基準・投入閾値の変更は、四半期見直しか否かを問わず都度人間承認とする。変更後の最初のバッチは Stage 1 相当（バッチ単位の人間承認）に戻して運用する。**

---

### 領域 B. アウトリーチ (Outreach)

#### Stage B0 — 人間が全部やる
- **内容:** 人間が1通ずつ文面を書き、宛先を選び、手動送信する。エージェントは文面ドラフトの作成補助のみ（送信しない）。
- **前提条件:**
  - 承認済みリード（A0/A1 由来）が存在する。
  - メッセージングガイド（トーン、禁止表現、誇大広告禁止ルール）が承認済み。
- **human approval 必須ポイント:**
  - すべての送信（1通ずつ）。
  - メッセージングガイドの内容。
- **次段階（B1）へ進む判定基準:**
  - 定型テンプレート（初回・フォローアップ）が3〜5パターンに固まり、人間承認済み。
  - 返信分類ルール（ポジティブ / ネガティブ / opt-out / 不在）が定義済み。
  - opt-out 処理フロー（G2）が実装され、手動運用で回っている。

#### Stage B1 — 人間承認つき半自動
- **内容:** エージェントが承認済みテンプレートで宛先ごとにパーソナライズしたドラフトを **バッチ生成**し、宛先リスト・送信タイミング・レート設定とともに提示。**人間がバッチ単位で承認 → 承認後に送信**。フォローアップも同様にドラフト → 承認 → 送信。
- **前提条件:**
  - B0 の判定基準を満たす。
  - 送信前チェック（opt-out 照合 G2 / 重複・クールダウン照合 G5 / レート上限 G4 / ICP 合致 G1）が自動で走り、1件でも違反があればバッチを止める。
  - フォーム送信を伴う場合、CAPTCHA 検出で中断（G6）。
  - 全送信が監査ログに記録される（宛先、テンプレート ID、送信時刻、承認者）。
- **human approval 必須ポイント:**
  - 各送信バッチの実行承認（G7）。**初回の外部送信は必ずここで人間承認を取る。**
  - 新テンプレート・新チャネル（例: SNS DM 追加）の初回使用（G7）。
  - 価格・割引・契約条件・返金に触れる文面（G8）— これらは自動テンプレートに含めず、個別に人間が作成・承認。
- **次段階（B2）へ進む判定基準:**
  - 一定数以上のバッチで、人間の文面修正がごく軽微、かつ承認率が事前合意閾値以上。
  - opt-out / 重複 / レート違反のすり抜けがゼロで一定期間安定。
  - ネガティブ返信・苦情の発生率が事前合意閾値未満。
  - 返信分類の自動判定精度がサンプリング検証で合意水準に達する。

#### Stage B2 — 自動
- **内容:** 承認済みテンプレート・承認済みセグメントの範囲内で、パーソナライズ・送信・フォローアップ・返信分類・opt-out 処理を自動実行。人間は日次サマリの監査とサンプリング、例外対応。
- **前提条件:**
  - **Stage 2 への移行は、AGENT_GOVERNANCE.md §8 STOP LIST（エージェント自身による外部送信・公開の禁止）が人間の承認により改定されることを前提とする。改定前は本 Stage を稼働させない。改定は人間の明示的な指示によってのみ行われ、判定基準の充足・時間経過・運転モードの変更はいずれも改定を意味しない。**
  - B1 の判定基準をすべて満たす。
  - **自動送信文の可変部分は、事前承認済みの差込フィールド（会社名・担当者名・公開情報の引用等）に構造的に限定する。自由生成文を含める場合は、価格・性能・実績・機能に関する主張が無いことの自動チェックを通過したもののみ送信し、通過しないものは人間レビューへ回す。**
  - 「承認済みテンプレート × 承認済みセグメント」の組み合わせ以外は自動送信不可（範囲外は Stage 1 扱いに落ちる）。
  - 苦情率・バウンス率・opt-out 率が閾値を超えたら自動停止。
  - 1日あたり送信上限（G4）を超えない。
- **human approval 必須ポイント（Stage 2 でも残る）:**
  - 新テンプレート / 新セグメント / 新チャネルの追加は都度、初回送信前に承認（G7）。
  - 金額・契約・返金に関わる会話への遷移が検出されたら自動送信を止め、人間（Account Executive / CTO）へ引き継ぐ（G8）。
  - 送信上限・停止閾値の変更。
  - 規約変更（G3）が検知されたチャネルの再開承認。

### 領域 C. 商談 (Deals / Sales Process)

#### Stage C0 — 人間が全部やる
- **内容:** Account Executive が商談実施、メモ作成、CRM 更新、次アクション設定、見積作成をすべて手動で行う。エージェントは議事録の整形補助のみ。
- **前提条件:**
  - CRM のステージ定義とデータ項目が確定済み。
  - **確定した原則: アウトリーチ用の見込み客データを、既存の顧客向けマルチテナントスキーマへ混在させない。**
  - **CRM / opt-out ストアの所在（外部 SaaS か自社実装か）は未決の人間判断事項であり、`docs/decisions/TODO.md` に記録する。本文書では所在を決めない。**（外部 SaaS なら越境移転と処理者契約に直結し、自社 DB ならテナント資産ではない自社の見込み客データの置き場所を別途設計する必要がある。）
- **human approval 必須ポイント:** 見積・価格提示・契約条件・割引・返金のすべて（G8）。
- **次段階（C1）へ進む判定基準:**
  - CRM 更新の型（どのイベントで何を更新するか）が定型化。
  - 日程調整の往復パターンが定型化。
  - 見積の構成要素（プラン、数量、期間）が整理され、価格表のドラフトが存在する（※クレジット価格モデルとマージン、およびプラン定義は現時点で未決の人間判断事項である。これらが確定するまで C1 へ移行しない）。

#### Stage C1 — 人間承認つき半自動
- **内容:** エージェントが (a) 日程調整メールのドラフト生成（送信は B1 の承認フローに従う）、(b) 商談メモから CRM 更新案・次アクション案を生成して人間が確認後に反映、(c) 見積の**ドラフト**を生成（金額欄は人間が確定）。
- **前提条件:**
  - C0 の判定基準を満たす。
  - CRM 書き込みは「提案 → 人間承認 → 反映」の形をとる。
  - 見積ドラフトに「DRAFT / 価格未確定」の明示。
- **human approval 必須ポイント:**
  - 見積のすべての金額・条件（G8）。
  - CRM のステージ変更（特に「受注」「失注」）。
  - 顧客への日程確定連絡の送信（G7 / B1 フロー）。
- **次段階（C2）へ進む判定基準:**
  - CRM 更新案の人間承認率が高く、修正が軽微で一定期間安定。
  - 日程調整ドラフトがほぼ無修正で通る。
  - 誤った金額・条件がドラフトに混入した事例がゼロ。

#### Stage C2 — 自動
- **内容:** 日程調整の往復、商談メモからの CRM 更新（金額・受注/失注を除く）、次アクションのリマインドを自動化。人間は例外対応と週次監査。
- **前提条件:**
  - C1 の判定基準をすべて満たす。
  - 「金額」「契約条件」「受注/失注ステージ」「返金」は自動化対象から**恒久的に除外**。
  - 自動更新の全件が監査ログに残り、いつでも巻き戻せる。
- **human approval 必須ポイント（Stage 2 でも残る）:**
  - すべての価格・見積・契約・割引・返金（G8）— Stage が進んでも自動化しない。
  - 受注 / 失注の確定。
  - 顧客への外部送信のうち、新パターンの初回（G7）。

- **前提条件:** 問い合わせ受付チャネルと分類カテゴリが定義済み。
- **human approval 必須ポイント:** すべての顧客向け返信の送信。返金・契約・価格に関する回答（G8）。
- **セキュリティ事案の即時エスカレーション（全 Stage 共通・最優先）:**
  - セキュリティ・情報漏えい・他テナントのデータ露出の疑いは、分類した時点で自動処理を打ち切り、Michael 経由で Security & Reliability へ即時エスカレーションし、同時に人間へ上げる（AGENT_GOVERNANCE.md §3.7 準拠、最優先）。Stage に関わらず自動回答しない。

- **次段階（D1）へ進む判定基準:**
  - 分類カテゴリが安定し、FAQ が整備されている。
  - 「自動回答してよい質問」と「必ず人間が回答する質問（金額・契約・障害・セキュリティ・データ削除）」の線引きが承認済み。

#### Stage D1 — 人間承認つき半自動
- **内容:** エージェントが問い合わせを自動分類し、FAQ 該当分は**回答ドラフト**を生成。人間がレビュー・編集して送信。金額 / 契約 / 障害 / セキュリティ / 個人データに関わるものは自動でフラグを立て、人間へ直行。
- **前提条件:**
  - D0 の判定基準を満たす。
  - 回答ドラフトに引用元 FAQ を明示。
  - 誇大表現・未実装機能の言及を検出するチェック（PRODUCT_SPEC 準拠）。
- **human approval 必須ポイント:**
  - すべての顧客向け返信の送信（G7）。
  - 金額 / 契約 / 返金 に関わる回答内容（G8）。
  - FAQ（自動回答の元ネタ）の追加・変更。
- **次段階（D2）へ進む判定基準:**
  - FAQ 該当問い合わせでのドラフト採用率が高く、編集が軽微。
  - 誤分類率・誤回答（未実装機能を「ある」と答える等）の発生がゼロで一定期間安定。
  - 顧客満足度 / 苦情率が閾値内。

#### Stage D2 — 自動
- **内容:** FAQ に明確に該当する定型問い合わせに限り、自動で一次回答を返信。それ以外はすべて人間へ。人間は全自動回答のサンプリング監査と、フラグ付き問い合わせの対応。
- **前提条件:**
  - **Stage 2 への移行は、AGENT_GOVERNANCE.md §8 STOP LIST（エージェント自身による外部送信・公開の禁止）が人間の承認により改定されることを前提とする。改定前は本 Stage を稼働させない。改定は人間の明示的な指示によってのみ行われ、判定基準の充足・時間経過・運転モードの変更はいずれも改定を意味しない。**
  - D1 の判定基準をすべて満たす。
  - 自動回答の対象カテゴリを明示的なホワイトリストで限定。信頼度が閾値未満なら自動回答しない。
  - 金額 / 契約 / 障害 / セキュリティ / データ削除 / 苦情 は自動回答から**恒久的に除外**。
  - 顧客が「人間と話したい」と示したら即座に人間へ引き継ぐ。
- **human approval 必須ポイント（Stage 2 でも残る）:**
  - 自動回答ホワイトリストへのカテゴリ追加（G7 相当）。
  - FAQ の内容変更。
  - 金額・契約・返金に関わる一切（G8）。

### 領域 E. コンテンツ (Content)

#### Stage E0 — 人間が全部やる
- **内容:** Marketing Manager が企画、Content Marketing が制作、人間が公開判断。エージェントは下書き・構成案まで。公開（SNS / Web）はしない。
- **前提条件:** メッセージングガイド、ブランドトーン、事実確認プロセスが承認済み。
- **human approval 必須ポイント:** すべての外部公開（ブログ、LP、SNS、事例）。事例・実績・数値の掲載（架空の導入企業・根拠なき性能を載せない）。

  - 事実確認（fact-check）フローが文書化され運用されている。
  - 公開前レビューの担当と基準が明確。

#### Stage E1 — 人間承認つき半自動
- **内容:** エージェントが企画に沿ってドラフト（記事、投稿、メールナーチャリング文面）を量産し、fact-check チェックリストを通したうえで提示。人間がレビュー・修正・公開承認。公開操作自体は承認後に人間または承認済みフローで実施。

  - **生成物をマーケティング素材に使用する場合、AI 生成である旨の表示を伴う。実際に撮影されたウォークスルー映像であるかのような表現、正確な寸法・間取り・眺望であるかのような表現をしない。存在しない窓・扉・設備・眺望を含む素材を販促に用いない。表示の正確な文言と位置は未決の人間判断事項（Legal 確認必須）であり、確定するまで生成物の対外使用は都度人間承認を取る。**
  - 配信レート・頻度上限（G4）が設定済み。
- **human approval 必須ポイント:**
  - すべての外部公開・配信（G7）。**初回公開は必ず人間承認。**
  - 新チャネル（新しい SNS、新しい配信先）の追加（G3 規約確認 + G7）。

- **次段階（E2）へ進む判定基準:**
  - ドラフトの人間修正が軽微で、公開承認率が事前合意閾値以上、一定期間安定。
  - fact-check ですり抜けた誤り（未実装機能、誇大表現、架空実績）がゼロ。
  - 配信頻度・レートの違反がゼロ。

#### Stage E2 — 自動
- **内容:** 承認済みテンプレート・承認済みチャネル・承認済みトピック範囲内で、ナーチャリングメールや SNS 投稿のスケジュール配信を自動化。人間は事前のトピックカレンダー承認と事後監査。
- **前提条件:**
  - **Stage 2 への移行は、AGENT_GOVERNANCE.md §8 STOP LIST（エージェント自身による外部送信・公開の禁止）が人間の承認により改定されることを前提とする。改定前は本 Stage を稼働させない。改定は人間の明示的な指示によってのみ行われ、判定基準の充足・時間経過・運転モードの変更はいずれも改定を意味しない。**
  - E1 の判定基準をすべて満たす。
  - 自動配信は「事前に人間が承認したコンテンツカレンダー / キュー」の中身に限る。新規生成物をレビューなしで即時公開はしない。
  - 数値・実績・顧客名・価格・比較を含むコンテンツは自動配信キューに載せない（人間レビュー必須のまま）。
  - **生成動画・生成画像を含むコンテンツは、AI 生成である旨の明示を伴わない限り自動配信キューに載せない**（表示の具体的な文言・位置は未決の人間判断事項）。
  - エンゲージメント異常・苦情・誤情報報告で自動配信を停止。
- **human approval 必須ポイント（Stage 2 でも残る）:**
  - コンテンツカレンダー / 配信キューの中身（配信前に人間が承認）。
  - 新チャネル・新トピック領域の追加（G3 + G7）。
  - 価格・実績・比較・顧客名を含む一切のコンテンツ（G8 / 誇大広告禁止）。
  - 配信頻度・停止閾値の変更。

## 4. 段階移行の共通判定原則

どの領域でも、Stage を1つ上げる判断は以下をすべて満たしたときのみ、人間 (CTO) が承認する。

1. **定型化:** 直前 Stage の作業が明確なテンプレート / ルールに落ちている。
2. **承認率:** 人間のレビューでの承認率が事前合意した閾値以上、かつ修正が軽微。
3. **無違反期間:** G1〜G8 のいずれの違反も、事前合意した一定期間・一定件数にわたり発生していない。
4. **監査可能性:** すべてのアクションが「誰が / いつ / 何を / どのデータソース・テンプレートで」の形で記録されている。
5. **停止機構:** 異常検知による自動停止と、手動での即時停止手段が実装・テスト済み。
6. **ロールバック:** 誤ったアクション（誤送信キュー投入、誤 CRM 更新、誤公開）を取り消す手順が定義・検証済み。**ただし送信済みのものは取り消せない。** 誤送信時の手順（送信の即時停止・影響範囲の特定・人間への即時報告・訂正／お詫びの要否判断・個人データが含まれる場合の監督官庁報告と本人通知の要否を Legal が判定）を別途定義し、**Stage 1 移行前に整備する**。

いずれかが崩れた場合、その領域は自動的に1つ下の Stage の運用に戻す（デグレード運用）。

## 5. Stage 2（完全自動）でも恒久的に自動化しない事項

Stage が最終段階に達しても、以下は常に人間承認を要する（G7 / G8 の帰結）。

- 価格の確定・提示、割引、契約条件、返金、無償提供（G8）。
- **可用性・SLA・復旧時間・納期・生成所要時間・品質水準の対外的な表明（G8）。**
- **個人データの利用目的の追加・変更、第三者提供、国外移転、保有期間・削除基準の変更（G9）。**
- 新しいデータソース / 送信チャネル / SNS プラットフォームの追加（G3 規約確認 + G7 初回承認）。
- 新テンプレート・新セグメント・新トピックの初回外部使用（G7）。
- 実績数値・顧客名・比較表現・導入事例の対外公開（誇大広告禁止 / 架空実績禁止）。
- レート上限・自動停止閾値・クールダウン期間の変更（G4 / G5）。
- CAPTCHA / bot 検知に遭遇したケースの対応（G6：自動処理せず人間へ）。
- opt-out 運用ルールの変更（G2）。
- 顧客からの苦情・障害報告・セキュリティ / データ削除依頼への対応（D 領域）。
